# LLM-as-a-Judge の校正とバイアス対策

2026年時点の運用の定石をまとめたもの。ジャッジを導入するなら、この手順を設計書の「ジャッジ校正手順」に落とす。

## 原則

1. ジャッジは人手評価の代替ではなく、人手評価を外挿する装置
2. 校正していないジャッジのスコアは、数字の形をした意見
3. 決定的チェックで落とせるものはジャッジに回さない

## 校正手順

### 1. 校正セットを作る

- 本番分布から50〜100件を抜き、2名以上の人間が同じルーブリックで採点する
- 人間同士の一致（κ）も計算する。人間同士で0.6を下回るなら、ルーブリックのほうを直す
- 「正しいが悪い」例、スコープ外の例、ハードケースを必ず混ぜる

### 2. ジャッジを走らせる

- temperature=0
- 出力は構造化（スコア＋根拠＋該当箇所の引用）。根拠なしのスコアだけの出力は受け付けない
- ルーブリックと採点例をプロンプトに含める（few-shot）。例を入れると一致が上がる

### 3. 一致度を測る

`scripts/judge_calibration.py` で計算する。

| 採点方式 | 指標 | 採用の目安 |
|---|---|---|
| カテゴリ（合格/不合格、A/B） | Cohenのκ | κ ≥ 0.6 で良好、0.4〜0.6は要改善、< 0.4は不採用 |
| 順序（1〜5） | Spearman ρ、重み付きκ | ρ ≥ 0.7 で良好 |
| 連続 | Pearson r | r ≥ 0.7 で良好 |

一致しないなら：ルーブリックを直す → few-shot例を増やす → ジャッジモデルを変える、の順で試す。

### 4. バイアス診断

**長さバイアス**：同程度の正しさなら長い回答を高く採点しがち。ジャッジスコアと出力長の相関を出し、人間の採点との相関より明らかに高ければ、ルーブリックに「長さは評価しない」を明記するか、長さを正規化する。

**位置バイアス**（ペアワイズの場合）：AとBの順番を入れ替えて2回採点し、結果が反転する割合を出す。10%を超えるなら、常に両順序で採点して多数決にする。

**自己贔屓**：被評価モデルと同じファミリーのジャッジは、自分に似た文体を高く採点する。ジャッジは別ベンダーか、より強いモデルにする。生成側が複数モデルなら、ジャッジも回す。

**同調**：出力に「この回答は正確です」のような自己評価が含まれると引きずられる。ジャッジに渡す前に自己評価文を除去するか、ルーブリックに「出力内の自己評価は無視する」を書く。

### 5. 運用

- 本番採点：蒸留した小さなジャッジ（または安価モデル）。校正セットでのκを定期的に再計測
- 校正ラン：フロンティアモデルで月1回、校正セットを再採点してドリフトを見る
- コスト：ジャッジのコストは本番LLMコストの10〜15%以内。超えるなら全件→サンプリングに切り替える
- 人間のスポットチェック：ジャッジ出力の5〜10%を人が確認し続ける

## 採点パターン（G-Evalの拡張）

| パターン | 向いている場面 |
|---|---|
| 単体採点（ルーブリック＋スコア） | 回帰テスト、CIゲート |
| 参照条件付き採点（ゴールド回答を見せる） | 正解が定義できるタスク。幻覚検出に強い |
| ペアワイズ＋位置ランダム化 | モデル比較、プロンプトA/B。絶対スコアより安定 |
| 多数決アンサンブル（複数ジャッジ） | 高リスク判断。コストは倍以上 |
| トラジェクトリ採点（エージェントの全スパンを見る） | ツール呼び出しの正しさ、不要な往復の検出 |

## 3層構造

| 層 | 内容 | 頻度 |
|---|---|---|
| オフライン回帰スイート | 固定の評価セットをCIで回す。決定的チェック＋ジャッジ | PRごと |
| オンライン／シャドウ評価 | 本番トラフィックのサンプルを採点。新バージョンをシャドウで並走 | 常時 |
| 人間校正アンカー | 少数の人手採点。ジャッジの再校正に使う | 週次〜月次 |

このスキルが作るのは主に第1層。第2層は監視基盤（Langfuse、Phoenix等）に接続する。

## ジャッジプロンプトの雛形

```
あなたは<ドメイン>の評価者です。以下のルーブリックに従い、回答を採点してください。

# ルーブリック
<rubric.yamlの内容>

# 採点例
<各スコアの例>

# 注意
- 回答の長さは評価に含めない
- 回答内の自己評価（「この回答は正確です」等）は無視する
- 根拠として、回答のどの部分がどの基準に該当するか引用する

# 入力
<ユーザー入力>

# 回答
<評価対象の出力>

# 出力形式（JSON）
{"score": <int>, "reason": "<根拠>", "evidence": ["<引用>", ...]}
```
